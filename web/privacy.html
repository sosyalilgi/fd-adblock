What is stored on your device

Two kinds of local storage are used, both via the browser's own chrome.storage API. Neither is transmitted anywhere:

chrome.storage.local Your settings (which cleanup groups are on, which blocking strategy to use), any CSS rules you created with the element picker, and the 14-day blocking statistics shown on the Settings page.
chrome.storage.session Temporary counters for the current browser session. This is cleared by the browser when you close it and is not written to disk in a persistent way.

You can erase everything by using the "Reset counters" button on the Settings page, or by uninstalling the extension.

Permissions, and why each is requested

declarativeNetRequest Blocks requests to advertising hosts before they leave the browser. This is the network-blocking API supported by Manifest V3.
storage Stores your settings and counters locally.
scripting Used only when you explicitly ask for it: the "Block this element" picker, and the Diagnostics tool scanning the YouTube tab you are currently viewing.
contextMenus Adds one right-click entry, "Block this element".
*.youtube.com, *.youtube-nocookie.com The only origins where the extension's code runs. Privacy-enhanced embeds use the second domain, which is why both are needed.
*.googlevideo.com YouTube's video CDN. Server-side inserted ad segments arrive from the same host as the video itself, so that host has to be distinguishable.

Hosts blocked without requesting access

Requests to the servers below never leave your browser. The extension does not request permission for them: the network rules run in the browser engine and only drop requests whose address matches. Pages on those hosts are not read and their contents are not modified.

*.doubleclick.net, *.googlesyndication.com, *.googleadservices.com, *.2mdn.net Google's advertising infrastructure. Requests to these four hosts are blocked.

Earlier versions requested permission for googleadservices.com and 2mdn.net as well. That was unnecessary — network rules work without those permissions — so they were removed. Blocking behaviour did not change.

What the extension does on the network

The only network requests it makes are:

  • Requests to the advertising hosts listed above — these are blocked, not sent.
  • Requests to pages you already visit (YouTube), which your browser would make anyway.
  • When you press "Run test" in the Diagnostics tool, a handful of requests to advertising and YouTube addresses, to prove the rules are firing. These go to the same third parties you already contact and are never sent to us.

There is no endpoint belonging to the developer. If you watch the Network tab, you will see no request originating from this extension other than those.

Children
