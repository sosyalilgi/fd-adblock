First, run the diagnostics

Most questions are answered faster by the built-in tool than by guessing. Open the extension popup and click Diagnostics, then pick your YouTube tab. It reports which layers are working on that page.

If it says "Content script not loaded" or the panel looks stale, reload the extension from chrome://extensions and then reload your YouTube tab with Ctrl+Shift+R.

Common questions

An ad still appears. What should I check?

Run Diagnostics and look at these three lines:

  • Leaked ads — if this is not empty, an element slipped past the cosmetic filters. Right-click it and choose Block this element to add a permanent rule.
  • Ad placement pruning — Source should read budama kaydı or ytInitialPlayerResponse. If it says couldn't find a player response, reload the page.
  • Player — if ad-showing is on, the fallback should kick in. If speed is above 1×, an ad is being fast-forwarded.

YouTube shows an "ad blocker detected" notice

Open Settings → Anti-detection and turn it on, then reload the page. This option is off by default — we prefer to show you what we do rather than hide it.

Note: after changing this setting you must reload the page. Hooks that are already installed cannot be reliably removed.

Something is hidden that I want to see

Settings has seven independent cleanup groups. Turn off the one hiding what you need — for example Shorts — home page if Shorts shelves disappeared from the home feed.

The counters look wrong (for example ads blocked = 0)

Session counters reset when the browser closes. Also, after reloading the extension you must reload your YouTube tab — the old content scripts become detached and can no longer report anything. Diagnostics has a "Counter consistency" card that flags exactly this.

Some videos are server-side inserted

YouTube stitches some advertisements directly into the video stream on the server. No browser extension can block these, because the ad and the video are the same bytes. Most in-video ads are still client-side and are blocked here; some never will be.

Reading the network test

In Diagnostics, Run test disables the network rules, re-enables them, and compares. A row is counted as proof only when the request fails while rules are on and succeeds while rules are off.

The robots.txt row is a control: it must always succeed. If it ever fails, the whole test is invalid and the result is discarded rather than reported — a control that fails is treated as "no measurement", not as "something is broken".

Keyboard shortcut

Alt+Shift+Y opens the extension menu.

Reporting a problem

Please include:

  • What you expected and what happened instead
  • The Diagnostics report (Copy report button) — this is the fastest way for us to see which layer is failing
  • Your Chrome version from chrome://version
